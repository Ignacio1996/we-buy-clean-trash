Phase 9 · Admin polish

What Tia sees after Phase 8 lands: three new panels on the admin dashboard (zone performance, contamination alerts, operator leaderboard) and a new Compliance section for printing and mailing required residential notices. Everything is admin-only — sign in as Tia on a laptop.

⚠️ What's stubbed in this flow The metrics are real; the mailing step is not automated:
  • Compliance notices — the app generates the PDF batch. An admin then prints, stuffs, and mails them by hand, and clicks "Mark as mailed." No postage/automation integration during the pilot.

What you're verifying

  • The dashboard now shows a Zone performance table with per-zone residents, bags, weight, and revenue for the current month.
  • Contamination alerts list the residents with the most flagged bags over the last 6 months, labelled 1st warning / 2nd strike / 3rd+ strike.
  • The Operator leaderboard ranks operators this month by completed pickups, with an issues tie-breaker.
  • Tia can generate an Initial Service Notice and a Semi-Annual Update batch per zone, print one letter per resident, and mark the batch as mailed.
  • Mailed batches become an auditable record in Firestore (complianceBatches) with status, generated-by, mailed-by, and timestamps.
📋 Before you start

Device: 💻 Laptop (you're Tia for this whole guide).

Dependencies — these panels are data-driven, so earlier phases need to have run:

  • Phase 4 — 1 zone with 1 depot linked, plus 2–3 residents with addresses in the zone.
  • Phase 6 — at least one completed route.
  • Phase 7 — several processed bags, including at least a couple flagged Minor, Major, or Severe contamination (see Phase 7 Advanced · Scenario 5).
Scenario 1 — Read the zone performance table

Admin Signed in as Tia on a laptop.

  1. Open /admin.
  2. Scroll below the KPI tiles to Zone performance.
  3. Find the zone you've been testing in. Cross-check each column:
    • Residents should match the number of resident users Tia can count in /admin/users whose zone is this one.
    • Bags is the count of bagProcessing records for residents in this zone, this month.
    • Weight is the sum of every weight field on those bagProcessing records.
    • Revenue is the sum of bagOrders.total for the zone, this month, excluding cancelled orders.
Expected: Each zone row reflects exactly what Goode weighed this month, not cumulative totals. A brand-new month shows zero bags and zero revenue even if the zone has lots of historical activity.

Verify:

Zones with no resident activity still list (with zeros), not missing

A resident without a zoneId does not show up in any row

Revenue of a cancelled bag order does not appear

Scenario 2 — First-warning contamination alert

Depot + Admin Two tabs.

  1. As Goode, process one of Aguirre's bags with contamination set to Minor. Submit.
  2. As Tia, reload /admin.
  3. Scroll to the Contamination alerts panel.
Expected: A row appears for Aguirre with the label 1st warning, the gray WARNED badge, her zone name, the severity (Minor), and the date Goode just submitted.

Verify:

A bag submitted with severity None does not add to the alerts list

The address / zone shown matches Aguirre's current address

Scenario 3 — Escalating to 2nd strike, then 3rd

Depot + Admin Same two tabs.

  1. As Goode, process a second Aguirre bag — Major contamination.
  2. As Tia, reload /admin. Aguirre's row should now read 2nd strike with an amber STRIKE badge.
  3. As Goode, process a third Aguirre bag — Severe.
  4. As Tia, reload again. The row flips to 3rd strike with a red ACTION badge.
Expected: The strike count is the total number of non-clean bagProcessing records for this resident across the last 6 months, regardless of severity. Severe does not count for more than Minor — the severity is only shown as the "last" value for context.

Verify:

Badge color matches the count (gray at 1, amber at 2, red at 3+)

A fourth flagged bag shows 4th strike (still red ACTION)

Most-struck residents sort to the top

Scenario 4 — Operator leaderboard

Operator + Admin Two tabs.

For this scenario the leaderboard only reads pickups.status = 'completed' (and counts issue / skipped / missed into the issues column). You only need one operator active to see data — more makes the ranking obvious.

  1. As Aguirre the operator, complete a couple of pickups for today's route (Phase 6).
  2. On the same route, tap Not out or Issue on one stop to generate an issue count.
  3. As Tia, reload /admin and look at Operator leaderboard.
Expected: Aguirre's name appears with a 🥇 medal icon, his completed pickup count, and "1 issue" (or however many Not-Out/Issue/Skipped actions he did today). The list is capped at top 5.

Verify:

Completed pickups from before the 1st of this month are not counted

If two operators tie on completions, the one with fewer issues ranks higher

Pickups that are still pending don't affect either column

Scenario 5 — Generate an Initial Service batch

Admin Signed in as Tia.

  1. Open /admin/compliance (or click the new 📋 Compliance tab in the sidebar).
  2. In the Generate a new batch form, pick the pilot zone and leave the notice type on Initial Service Notice.
  3. Optionally type a note (e.g. "First mailing — Kirk USPS drop").
  4. Click Generate batch · N letters. The button shows the count based on how many residents the zone currently has.
Expected: A new row appears at the top of Recent batches with the zone name, type, resident count, an amber GENERATED badge, and today's date. No letters have been printed or mailed yet — that's still Tia's call.
📩 Initial Service gating (NEW · Apr 27)

Initial Service Notices skip residents whose service has already started — anyone with at least one completed pickup. The form says so, and the generated batch row reads something like "12 units · 3 active residents skipped". Semi-Annual updates still go to every resident in the zone (no gating).

The included resident UIDs are snapshotted onto the batch doc (residentIds field), so reprints later — even after more residents start service — produce the same letters. Pre-gating batches without that field fall back to "all residents in zone."

Verify:

The resident count on the row matches the one the form offered before clicking

The note (if entered) shows up in the row subtitle

An empty zone (0 residents) still generates a batch but its print view shows the empty-state

NEW: After processing a bag for one resident in the zone, generating a fresh Initial Service batch shows that resident as "skipped" — Semi-Annual still includes them

NEW: Re-printing the original batch still produces letters for the same N residents (snapshot is immutable)

Scenario 6 — Print the letters

Admin Signed in as Tia.

  1. On the batch row, click Print letters. A new tab opens at /admin/compliance/[batchId]/print.
  2. Scroll through the preview — there should be one letter per resident, with the resident's name, street address, zone pickup day, depot location, and the list of accepted materials.
  3. Click 🖨️ Print all letters. The browser print dialog opens.
  4. Choose Save as PDF to verify the output; or send to an actual printer.
Expected: The admin sidebar, header, and the two buttons at the top of the screen all disappear in the print preview. Each resident's letter begins on its own page (CSS break-after-page). Letters are sorted alphabetically by street.

Verify:

One page per resident — no two letters share a page

The "Semi-Annual Update" copy is different from the "Initial Service" copy (test by generating both types and comparing)

Residents without an address on file are silently skipped (pilot choice)

Scenario 7 — Mark the batch as mailed

Admin Signed in as Tia.

  1. Back on /admin/compliance, find the batch.
  2. Click Mark as mailed.
  3. The row's badge flips from amber GENERATED to green MAILED, and the subtitle gains a "Mailed [date]" note.
Expected: The Mark as mailed button disappears (idempotent — no accidental double-mark). In Firestore, the complianceBatches document has status = "mailed", a mailedAt timestamp, and Tia's uid in mailedBy. Print letters is still available for re-prints.

Verify:

Clicking Mark-as-mailed twice does nothing (button disappears after the first click)

Green MAILED badge persists across page reloads

mailedBy is Tia's uid, not the resident's

Scenario 8 — Semi-Annual update batch

Admin Signed in as Tia.

  1. Generate a second batch for the same zone — this time pick Semi-Annual Update.
  2. Open its print view.
Expected: The heading on each page reads Semi-Annual Recycling Service Update (not Notice of New Residential Recycling Service). The body copy says this is the required semi-annual update and invites contact-info corrections. The service-details table is the same (pickup day, depot, accepted materials, holidays).

Verify:

Both batches coexist — the first stays in the list

Each batch is independently mailable

Quick troubleshooting

What you see Likely cause What to try
Zone performance table is empty No zones created yet. Open /admin/zones and create at least one.
A zone's bags and weight are 0 but Goode processed bags this week The resident those bags belong to doesn't have the zone assigned. Open /admin/users, find the resident, confirm zoneId matches.
Contamination alerts never populate Every processed bag used severity None. Have Goode flip a couple of bags to Minor / Major / Severe in Phase 7, then reload the dashboard.
Leaderboard missing the operator I just watched complete pickups Those pickup docs don't have an operatorId set, or the completions happened before the 1st of the month. Check pickups in Firestore for a status = completed doc with the expected operatorId. Historical months are intentionally ignored.
"Generate batch" form disabled There are no zones yet. Create a zone first in /admin/zones.
Print view shows "No residents with addresses in this zone" The zone has residents but none have a linked addressId (rare once residents finish signup). Have the affected resident re-run onboarding, or fix the users.addressId field directly in Firestore for seeded accounts.
Print output still shows the admin sidebar / nav Browser's print media query isn't applying — check the print dialog's "Options → Headers and footers" and "Background graphics" switches. Turn Background graphics OFF in the print dialog. The layout uses print:hidden which is driven by the media query.

What's not testable yet

Real mailing automation (Lob, Click2Mail, etc.) is out of scope for the pilot — Tia prints letters and drops them in a USPS box, then comes back here to mark the batch mailed. Per-resident opt-out tracking and automatic semi-annual reminders are future work; today the admin just remembers to generate a new Semi-Annual batch every six months. Contamination strikes are read-only — the app does not yet send a warning email or SMS when a resident crosses a threshold; Tia takes that action manually.

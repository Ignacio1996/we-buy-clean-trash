Phase 5 · Building a Pickup Route

How Tia turns "these residents need a pickup" into a driving plan for Aguirre. This is the bridge between the admin dashboard (Phase 4) and the operator app (Phase 6) — you need to run this one before operator testing will work.

⚠️ What's stubbed in this flow
  • Operator assignment notification — Aguirre sees the route when he opens the app; no SMS or push is sent for the pilot.
  • The Google Maps Routes API call itself is not stubbed — it runs for real, so you'll see genuine optimized ordering.

What you're verifying

  • Tia can pull up pending pickups and bag-order deliveries for a zone.
  • The route optimizer returns an ordered list of stops.
  • Tia can assign the route to an operator by name.
  • When a resident places a bag order, it gets enqueued onto the next open route for that zone.
📋 Before you start

Device: 💻 Laptop (you're Tia for this whole guide).

Dependencies — tick each before running Scenario 1:

  • Phase 4 — Tia has invited an operator (Aguirre) and he has accepted.
  • Phase 3 · Scenario 4 — at least one resident has scanned a bag for pickup (Aguirre).
  • Phase 3 · Scenario 3 — a second resident has a pending bag order (Goode).

Skipping any of these leaves the route empty — the builder has nothing to schedule.

Scenario 1 — Build tomorrow's route

Admin Signed in as Tia Johnson.

  1. In the admin sidebar, click Routes.
  2. Click New route.
  3. Pick tomorrow's date.
  4. Pick the zone Aguirre and Goode live in.
  5. Click Pull pending stops.
Expected: Both Aguirre and Goode appear in the stop list. Aguirre has a pickup (her scanned bag). Goode has a delivery (his bag order). Each stop shows the address and what's happening there.

Verify:

Both residents appear in the stop list

Pickups and deliveries are visually distinguished

Scenario 2 — Optimize the stop order

Admin Signed in as Tia Johnson.

  1. With the stop list showing, click Optimize order.
  2. Wait a moment.
Expected: The stops get reordered into a sensible driving sequence. A small map preview shows the resulting path. The total estimated drive time and distance show at the bottom of the list.

Verify:

Stop order changes after clicking Optimize

Map preview matches the new order

Scenario 3 — Assign and save

Admin Signed in as Tia Johnson.

  1. In the Operator field, pick Operator Aguirre.
  2. Click Save route.
Expected: The route appears in the routes list with status scheduled, tomorrow's date, and Aguirre's name. If you sign in as Aguirre (on a different device or private window) he should see the route on his operator home screen.

Verify:

Route saves and appears in list

Aguirre can see the route after the save

Scenario 4 — Late bag order joins the route

This scenario tests that an order placed after the route is built still gets picked up, by being tacked onto the next open route.

Resident Signed in as Resident Goode on his phone.

  1. Have Goode order another sheet of bags (repeat Phase 3, Scenario 3).
  2. Now sign back in as Tia and reopen tomorrow's route.
Expected: Goode's new order has automatically been added to the existing route's delivery list — Tia doesn't have to click anything. The stop count goes up by one if Goode wasn't already on the route, or the existing stop now shows the additional delivery.

Verify:

New order attaches to the open route without admin action

Scenario 5 — Edit a route

Admin Signed in as Tia Johnson.

  1. Open an existing scheduled route.
  2. Remove a stop manually using its × button.
  3. Re-run Optimize order.
  4. Save.
Expected: The edit sticks. If Aguirre was viewing the route at the same time he should see it update on the next reload.

Verify:

Removing a stop works

Re-optimization doesn't bring the removed stop back

Things to try that should fail

  • Trying to save a route with no operator assigned — the save button should be disabled or the form should block you.
  • Building two routes for the same date, same zone, same operator — you should get a warning or a clean error.
  • Picking a date in the past — not allowed.
If the map doesn't load. The route builder uses Google Maps. If the map tile is blank or the optimize button errors out with a Google-related message, the Maps API key may not be configured — flag it to the dev team, don't keep retrying.

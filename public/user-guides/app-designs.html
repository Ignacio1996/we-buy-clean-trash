Implementation Status — April 23, 2026 · All phases complete

Snapshot of build progress against the 12-phase plan. Latest commit: phase 11. Phase 12 is non-code (pilot launch on real customers).
✅ BUILT
Phase 0 — Foundation: Next.js 15 + TS + Tailwind, src/lib/firebase client + admin, Firebase project linked, env wired, Vercel deploys.
✅ BUILT
Phase 1 — Auth & role routing: Email/Google signup, /api/signup sets resident claim, middleware.ts gates by role, full invite flow (/api/invites, /invite/[token], /api/accept-invite) for operator / depot / manager / admin.
✅ BUILT
Phase 2 — Shared types + logic: 17 Firestore doc types under src/lib/types, pure functions in src/lib/logic (calculatePoints, calculateBagOrderTotal, pointsToDollars).
✅ BUILT
Phase 3 — Resident flow: Pre-signup scan (Gemini 2.5 Flash, session-only), signup w/ address + zone assignment, 3-step onboarding, home dashboard, order bags (Stripe stub), scan-bag (jsQR + manual fallback + photo), payout calculator, recycling guide, rewards (Amazon/Walmart redeem; Pay Bill + Donate are disabled stubs as planned), profile.
✅ BUILT
Phase 4 — Admin core: KPI dashboard, users + invites pages, zones & depots CRUD, yellow-sheet pricing editor (snapshots to priceHistory), redemption queue (Mark fulfilled).
✅ BUILT
Phase 5 — Routes: Admin route builder, /api/route-optimize (Google Maps computeRoutes + waypoint optimization), /api/bag-orders atomically enqueues onto next pending route for that zone.
✅ BUILT
Phase 6 — Operator flow: Today's Route w/ stat row + big Complete button, per-stop scan/photo/issue page, sticker-batch deliver page, "Driver on the way" SMS stub trigger, end-of-route summary.
✅ BUILT
Phase 7 — Depot flow: Incoming deliveries list, per-route detail, Process Bag form (7 weight fields + contamination picker → /api/process-bag writes bagProcessing + transactions + bumps users.pointsBalance + updates inventory + SMS stub in one transaction), inventory page.
✅ BUILT
Phase 8 — Depot Manager: Depots overview, depot detail, Schedule Mill Pickup form (/api/mill-shipments), Monthly Report PDF export.
✅ BUILT
Phase 9 — Admin polish: Zone Performance table, Contamination Alerts w/ rolling 6-month strike logic (1st warning → 2nd strike → 3rd action), Operator Leaderboard, Compliance Notices (PDF generate + Mark as mailed).
✅ BUILT
Phase 10 — QR generation: /api/qr-sheet generates Rollo-sized PDF with 10 QR + printed-number stickers, atomically creates stickerSheets + 10 bags; /api/qr-sheet/[id]/printed marks sheets as printed.
✅ BUILT
Phase 11 — Security & deploy: firestore.rules now enforces per-role reads (residents see only their own docs; operators see only their assigned routes; depot staff see their depot's bags; manager sees only their zone; admin sees all) — all client writes still denied, every privileged write goes through Admin SDK. storage.rules scopes evidence photos to the right roles. Comprehensive seed-pilot.ts idempotently creates the pilot zone, depot, admin, operator, depot worker, and 5 residents.
✅ BUILT
Phase 12 — Pilot onboarding: Out-of-code pilot work (print stickers on Rollo, hand-deliver first bag batch, collect in-person feedback). Tracked separately from the codebase.
Known divergences from this design doc

🟡 Stripe, Twilio SMS, Amazon/Walmart fulfillment, and "Pay Trash Bill" / "Donate" are all stubbed exactly as planned (mock checkout, console+smsLog writes, manual admin fulfillment queue, disabled buttons).
🟡 Mockup numbers (1,024 residents, 8.4k bags, etc.) are illustrative — the live admin dashboard pulls real counts from Firestore.

All previous open questions have been resolved. Ready to start coding.

+ NEW Operator: Bag + QR Sticker delivery screen. Phase 1: plain bags + separate QR sticker sheets delivered to residents. Each sticker has QR code + printed number as fallback.
UPDATED Operator: QR scan screen now shows both QR code and printed number. Manual entry says "type the number printed next to the QR".
UPDATED Depot: Processing screen now has per-commodity weighing — open bag, sort on table, weigh PET/aluminum/tin/cardboard/paper separately. Replaces single "total weight" field. Points auto-calculated per material.
UPDATED Depot: Inventory now shows 7 material categories individually instead of just "cardboard" and "commingled".
UPDATED Admin: Yellow Sheet now reflects all 7 commodity categories.
Resolved Decisions (previously pending)
✅ QR vs barcode → Using QR codes. Each QR has a printed number next to it as fallback.
✅ QR sticker model → Phase 1: Send plain bags + QR sticker sheets. Phase 2 (at scale): Manufacturer prints QR directly on bags.
✅ Categories → 7 categories: aluminum, tin, cardboard, paper, PET, HDPE, mixed plastic.
✅ Weighing process → Each commodity weighed separately after opening/sorting the bag. Replaces paper + Excel process.
✅ Voice prompts → Replaced with big "Complete" button. Voice/AI too complex for now.
✅ AI at depot → Not for now. Too expensive at scale. Keep it simple, functional first. AI only on resident scan-and-estimate feature.
✅ Bags reorder → Top of hierarchy on home screen. Main revenue stream = bag sales.
✅ Recycling education → Simple good/bad examples on a guide screen. More tutorials later with real user data.
✅ Rewards model → Points linked to gift cards (Amazon, Walmart). 100K pts = $10. Pilot: ~$1,000 in gift cards for ~100 users in local area.
✅ Invoicing → Monthly, end of month (e.g., April 30).

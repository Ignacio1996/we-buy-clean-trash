Admin Testing as an admin

The back-office role. You have the most surface area — invites, zones, pricing, redemptions, routes, sticker sheets, compliance mailings. Do this in two sessions: foundation setup first, then polish and operations.

Device: 💻 Laptop exclusively.
Who you'll be: Tia (tia.admin@wbct-pilot.test).

⚠️ What's stubbed in this flow As admin you see the back-end of every stub — expect:
  • Bag orders — residents never actually pay. Stripe is mocked, so every order lands as paid.
  • Gift card redemptions — requests pile into your queue for manual fulfillment. No auto-issue.
  • Compliance notices — the app generates a PDF; you print + mail it, then click "Mark as mailed."
  • SMS — all outbound texts are written to a Firestore smsLog collection (and the server console), not actually sent.
  • Invite emails — not sent. Copy the invite link from the admin UI and forward it yourself.

Your testing path

Session 1 — foundation (~30 min)

Every other role depends on this session. Run it first, then hand off to residents / operator / depot worker before coming back for Session 2.

1

Sign in and read the overview dashboard

Confirm KPIs load (may be zero), sidebar is visible, no "TODO" placeholders.

→ Admin dashboard · Scenario 1

2

Invite the operator and the depot worker

Send invites. For depot worker, the Depot dropdown must appear (link them to the pilot depot). Confirm the invites show as pending and the links are copyable.

→ Admin dashboard · Scenario 2

3

Create zones and a depot, configure accepted materials

Check existing pilot zone, add a test one, edit, delete. Create a depot and tie it to the zone.

Apr 27 addition: on each depot card, toggle the accepted materials chips so the depot only processes the commodities it actually handles. The depot worker's process form will hide the rest.

→ Admin dashboard · Scenarios 4 & 4b

4

Set Yellow Sheet prices, add custom materials, schedule campaigns

Without prices, the resident calculator and depot processing both show zero points.

Apr 27 additions: add new materials (compost / textile / electronics) via the + Add to yellow sheet composer; toggle the Active checkbox to hide a retired commodity (soft-delete only). In the new Pricing campaigns section below the table, schedule a global ×N multiplier for selected materials over a date range — Aguirre and Goode both see it live.

→ Admin dashboard · Scenarios 5 / 5b / 5c

5

Pre-generate sticker sheets

Generate a sheet, inspect the print preview, confirm it writes 1 sheet doc + 10 bag docs.

→ QR sticker generation · Scenarios 1–3

6

Build tomorrow's route

Pull pending pickups + deliveries for a zone, optimize stop order, assign the operator, save.

→ Route builder · Scenarios 1–3

Handoff. At this point operators and residents can start testing. Come back to Session 2 once they've generated some data — contamination flags, completed routes, processed bags — so the polish panels have something to display.
Session 2 — polish & operations (~20 min)

Run after the operator + depot testing has generated data. The panels below are data-driven and empty until then.

7

Read the polish panels

Zone performance table, contamination alerts (with escalating strike levels), operator leaderboard — all should reflect what the other roles just did.

→ Admin polish · Scenarios 1–4

8

Generate a compliance notice batch

Initial Service Notice or Semi-Annual Update — app generates the PDF, you click "Mark as mailed" after sending. No postage automation during the pilot.

Apr 27 addition: Initial Service batches now skip residents whose service has already started (any completed pickup) and the batch row shows a "N active residents skipped" count. Semi-Annual still goes to everyone in the zone.

→ Admin polish · Scenario 5

9

Gift-card redemption queue

Approve a pending resident request. The card is emailed manually — the app just moves the request through states.

→ Admin dashboard · Scenarios 6–7

10

Post-deploy smoke test (optional)

After the dev team ships a production deploy, a 5-minute check that every role can still sign in and all the key pages load.

→ Post-deploy smoke test

What you're not testing

  • Automatic gift-card fulfillment — manual email only.
  • Automated compliance mailings — generate + mark-as-mailed only.
  • Real email delivery of invites — logged to console during the pilot.

Compost · Operator — Bin-fullness route

How a compost driver runs the day: Start run, work the sites (tap a site, pick fullness per bin, submit), then End run for a summary. No scale needed — the server runs the bin-weight lookup. Pickups recorded while a run is open attach to it automatically. Run as Operator Aguirre.

⚠️ Prerequisites
  • An admin onboarded at least one commercial site in the operator's zone — see Compost · Admin: Commercial accounts.
  • That site has at least one bin provisioned (or the operator uses the manual-entry row).
  • For scanning: the bins carry printed QR labels — see Print QR labels in Compost · Admin: Commercial accounts. (Scanning is optional; tapping the bin row from the list still works.)
  • Today is one of the site's collection days, or you're testing an off-day pickup (still allowed — sites just won't show the TODAY badge).

What you're verifying

  • The compost-route banner appears on /operator when commercial sites exist in the operator's zone.
  • Today's sites surface above the rest with a TODAY badge.
  • The site stop screen shows one row per provisioned bin.
  • Scanning a bin's QR label jumps to (highlights + scrolls to) that bin's row; an unknown code warns and falls back to a manual bin.
  • Picking a fullness bucket updates the per-row weight estimate live.
  • Total weight = sum across all rows with content.
  • Submitting writes a binPickups doc and increments commercial inventory.
  • Start run opens a compostRoutes record; pickups taken while it's open carry its routeId; End run freezes a summary (stops · skipped · carts swapped · lbs · damaged).
  • An admin can review any past run at /admin/compost/routes.
Scenario 1 — Open the compost route

Operator Signed in as Operator Aguirre, on a phone.

  1. Land on /operator.
  2. Look for the blue banner: 🥬 Compost route — N sites in zone.
  3. Tap it. You land on /operator/compost.
Expected: Today's sites bubble to the top with a TODAY badge in the top-right corner of the card. The other sites (different collection days) sort alphabetically below. Each card shows zone, bin count, pickups/week, and the days the site is collected.
Scenario 2 — Start your run

The run is "the driver's day" — one record that all of today's stops hang off of, so the office gets a clean end-of-day tally instead of loose pickups.

  1. On /operator/compost, before working any site, tap the green ▶ Start run button near the top.
  2. The button is replaced by a mint Run in progress banner showing the start time and a live tally (0 stops · 0 lbs so far).
Expected: A compostRoutes doc is created with status: 'in_progress'. Starting again (double-tap / reload) does not create a second run — you get the same open one back. From here on, every pickup you record attaches to this run.

Verify:

The banner shows "Started <time>" in Columbus local time

Recording a pickup bumps the live tally (stops + lbs) after the page refreshes

You can still record without starting a run — those pickups just have routeId: null (ad-hoc)

Scenario 3 — Record a pickup at Comune (3 × 32-gal bins)

Comune was onboarded with three 32-gal bins. Today the driver finds the bins at ¾, ½, and full.

  1. Tap the Comune card. You land on /operator/compost/[id].
  2. Read the driver-notes amber banner if present (gate code, bin location).
  3. Material defaults to Food scrap. Leave it.
  4. Scan a bin (optional but recommended). In the Scan a bin card, tap 📷 Scan bin and point the camera at the bin's printed QR label (or type its BIN-NNNN number).
    • A match shows a green "✓ BIN-NNNN — set its fullness below" banner and highlights + scrolls to that bin's row.
    • A code not on this site's list shows an amber warning and adds it as a manual bin (in case you're at the wrong stop).
    • The scanner stays open so you can scan the next bin. Scanning is just a shortcut — you can always tap the right row by its printed number instead.
  5. Three rows are pre-rendered, one per provisioned bin. For each row tap the fullness bucket:
    • Bin 1 → 75% / Three-Quarter → reads ≈ 90 lbs
    • Bin 2 → 50% / Half → reads ≈ 60 lbs
    • Bin 3 → 100% / Full → reads ≈ 130 lbs
  6. Watch the blue Total weight panel at the bottom — it should update live to 280 lbs across 3 of 3 bins with content.
  7. Leave contamination on None.
  8. Add a note like "Hot day, lid was open" (optional).
  9. Tap the green ✓ Record pickup CTA.
Expected: You bounce back to /operator/compost. The card for Comune still shows TODAY (you might pick up again later). In Firestore: a new binPickups doc with totalWeightLbs: 280; the inventory doc commercial_<zoneId>_food_scrap incremented by 280.

Verify:

Total updates instantly when fullness changes

Submit is disabled when no row has fullness > 0

A site with zero bins falls back to a single manual-entry row that lets you pick a size and fullness ad-hoc

Scanning a provisioned bin's QR highlights + scrolls to its row

Scanning a code from another site shows the amber "isn't on this site's list" warning

Scenario 4 — End your run & read the summary

After the last stop, close out the day. The summary is computed from every pickup tied to the run — you don't tally anything by hand.

  1. Back on /operator/compost, in the Run in progress banner, tap the red End run button.
  2. The banner flips to a Run complete ✓ card with the day's tally, e.g. 12 stops · 1 skipped · 18 carts swapped · 2,340 lbs · 1 damaged.
  3. To begin another run later, tap Start a new run on that card.
Expected: The compostRoutes doc flips to status: 'completed' with endedAt set and a frozen summary. Only the operator who started the run can end it.

Verify:

"Carts swapped" counts bins on Swapped stops only (Loaded stops dump & return the same bins)

Skipped stops add to the "skipped" count but contribute 0 lbs

The same summary appears for the admin at /admin/compost/routes

Scenario 5 — 48-gallon weights

All bin sizes now use one linear formula — fullness × full-bin weight — matching the "Alternative Weight" column Tia's monthly reports actually aggregate. Full-bin weights: 32-gal = 130 lbs, 48-gal = 195 lbs, 64-gal = 260 lbs. So a 48-gal bin at 50% is exactly half of 195.

  1. Provision a 48-gal bin for any site (Compost · Admin scenario 2).
  2. On the operator stop screen, pick 50% on that row.
Expected: The row reads ≈ 97.5 lbs (195 × 0.5). These are treated as real values, not estimates — the linear model is the source of truth and reproduces Tia's three-year reporting history exactly, so the Phase C diversion reports do not footnote them.

Admin — review past runs

As Admin, open Compost → Route runs (/admin/compost/routes). It lists the most recent 100 runs with date, driver, the frozen summary line, and status (Completed / In progress). This is review-only — runs are created and closed by the driver on the road; there's no manual route-building or driver assignment (single-driver pilot — see the Commercial accounts guide for how sites surface to the driver by zone + collection day).

Edge cases worth poking

  • Material not accepted: Server rejects with material_not_accepted if the operator submits a material that isn't on the site's materialIds list.
  • Bin / size mismatch: If you somehow submit a bagId pointing at a 32-gal bin while the row says 64-gal, the server rejects with bin_size_mismatch.
  • Operator without a zone: If the operator's zoneId is unset, all active commercial sites show — useful for admin testing, not for production.
  • Photo capture: The form accepts an optional photo (wired but UI-deferred). Add it in a follow-up if drivers want to document overflow / contamination.

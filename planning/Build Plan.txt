# We Buy Clean Trash — Step-by-Step Build Plan

_Created April 16, 2026 · Pilot v1.2_

---

## Decisions locked in

- **Stack**: Next.js 15 (App Router, TS) + Tailwind + Firebase (Auth, Firestore, Storage, Cloud Functions) + Vercel
- **Structure**: single Next.js app at the repo root + sibling `functions/` dir for Cloud Functions. Shared pure logic lives in `src/lib/` and is imported by both. Mobile app (if built later) will live in a **separate repo** — not planned for here.
- **Auth**: Email/password + Google sign-in. Residents self-signup. Operators / depot workers / managers are invite-only (admin creates invite → email link)
- **AI scan**: Google Gemini 2.5 Flash (cheapest capable vision model)
- **Routing**: Google Maps Routes API with waypoint optimization
- **Maps target**: single-zone UI for pilot, multi-zone fields in data model
- **QR strategy**: app auto-generates printable QR sheets (Rollo thermal); each sticker has QR + printed number fallback
- **Driver-on-the-way alert**: tap-triggered by operator (no GPS geofence)
- **Scale**: manual weight entry
- **Compliance notices**: app generates PDF, admin clicks "Mark as mailed"
- **Firebase project**: `we-buy-clean-trash` (already created)
- **Vercel**: use default `*.vercel.app` for pilot

```
we-buy-clean-trash/
├── src/
│   ├── app/                          # Next.js 15 App Router
│   ├── lib/
│   │   ├── firebase/                 # client + admin SDK init

│   │   └── types/                    # TS types for Firestore docs
│   └── middleware.ts
├── functions/                        # Firebase Cloud Functions (own package.json)
│   └── src/index.ts                  # imports shared logic/types via tsconfig path alias
├── public/
├── firestore.rules
├── storage.rules
├── firebase.json
├── next.config.ts
├── tailwind.config.ts
├── tsconfig.json
├── package.json
└── planning/
```

**Sharing logic with Cloud Functions**: `functions/tsconfig.json` adds an `include` path for `../src/lib/logic` and `../src/lib/types`, plus a path alias so `functions/src/index.ts` can `import { calculatePoints } from '@shared/logic/calculatePoints'`. Pure files only — no Next.js, no React imports in `src/lib/logic` or `src/lib/types`.

## Data model (Firestore collections)

| Collection | Purpose |
|---|---|
| `users` | profile, role, zoneId, addressId, pointsBalance |
| `invites` | pending operator/depot/manager/admin invites |
| `zones` | zone name, depotId |
| `depots` | location, managerId, zoneIds |
| `addresses` | street, unit, geo, zoneId, residentId |
| `materials` | 7 commodities: marketPrice, customerPct |
| `bagOrders` | items, total, stripeStub, status, deliveryRouteId |
| `stickerSheets` | batch of 10, printedAt, residentId |
| `bags` | qrCode, printedNumber, stickerSheetId, residentId, declaredType, status |
| `pickups` | bagId, routeId, operatorId, photoUrl, completedAt, issue? |
| `routes` | date, zoneId, operatorId, orderedStops[], bagOrdersToDeliver[] |
| `bagProcessing` | bagId, weights{7}, separated, contaminationSeverity, pointsAwarded |
| `transactions` | ledger: signup_bonus, pickup, redemption (immutable) |
| `redemptions` | gift card requests — manual fulfillment queue |
| `inventory` | depotId × commodity → weight |
| `millShipments` | outgoing shipments |
| `contaminationFlags` | warnings/strikes per resident |
| `complianceNotices` | PDF generated + mark-as-mailed |
| `priceHistory` | historical yellow-sheet snapshots |
| `smsLog` | Twilio stub message log |

## Points math

```
pointsAwarded =
    Σ (weight_i × marketPrice_i × customerPct_i)
    × separatedMultiplier        // 2 if declared-separated, else 1
    × (1 − contaminationPenalty) // 0 / 0.3 / 0.6 / 0.9 (None / Minor / Major / Severe)
    × 10000                      // $ → points (100,000 pts = $10)
```

- Signup bonus: **+10,000 pts**
- Customer payout % per commodity is configurable in admin (default 30%)
- Contamination severity is set by the depot worker at processing time

---

## Bag order pricing

- Flat price per sheet of 10 bags
- **Free shipping** on orders ≥ $20
- **+$10 shipping** on orders < $20
- Bag order triggers the **next operator route** for that zone to deliver

## Build steps — ordered

### Phase 0 — Foundation (~half day)
1. `create-next-app` at repo root (App Router, TS, Tailwind, `src/` dir, ESLint). Add prettier
2. Create `src/lib/firebase/`, `src/lib/logic/`, `src/lib/types/` (empty for now)
3. Firebase CLI: `firebase init` at repo root (Firestore, Functions, Storage, Emulators, Hosting off). Functions lands in `functions/` with its own `package.json`
4. Configure `functions/tsconfig.json` to include `../src/lib/logic` + `../src/lib/types` with a `@shared/*` path alias
5. Env: `.env.local` with Firebase web config + placeholders for `GEMINI_API_KEY`, `GOOGLE_MAPS_API_KEY`, `FIREBASE_ADMIN_SA`
6. Vercel: link repo, set env vars, first deploy of the empty app

### Phase 1 — Auth & role routing (~1 day)
7. Firebase Auth: email/pass + Google provider enabled in console
8. Custom claims: Cloud Function on user create → default role `resident`; admin-triggered function assigns other roles via invite
9. Middleware: `src/middleware.ts` reads session cookie, redirects by role prefix (`/resident`, `/operator`, `/depot`, `/manager`, `/admin`)
10. Invite flow: admin creates `invites/{token}` → emailed link → accept page sets custom claim

### Phase 2 — Shared types + logic (~half day)
11. TS types for all Firestore docs in `src/lib/types`
12. Pure functions in `src/lib/logic` (no framework / React / Next imports — must be Cloud Functions-safe):
    - `calculatePoints({ weights, materials, separated, contaminationSeverity })`
    - `calculateBagOrderTotal({ quantity, unitPrice })` with $20 free-ship rule
    - `pointsToDollars(pts)`

### Phase 3 — Resident flow (~2 days)
13. **Public landing + pre-signup scan** (`/scan`): browser camera → `/api/scan` (Gemini 2.5 Flash vision) → show items + estimated earnings. Session-only (localStorage), no anonymous persistence.
14. **Signup**: email/Google → collect name, address → assign zone (reverse-geocode or admin-preset zip list) → create `users` + `addresses`
15. **Onboarding 3-step card** (Order bags → Schedule → Earn)
16. **Home dashboard**: points stat, next pickup card, Order More Bags (top), notification card, impact card, bottom nav
17. **Order Bags**: quantity stepper → total + shipping rule → Stripe placeholder button → creates `bagOrders` (status `pending_delivery`). Stub interface: `lib/payments/stripe.ts` with `createCheckoutSession()` returning a mock success
18. **Scan QR** (`/scan-bag`): jsQR-based camera scan + manual number fallback → pick bag type → photo upload to Storage → creates `pickups` pending
19. **Payout calculator**: reads `materials` collection live; shows good vs. contaminated scenarios
20. **Recycling Guide**: static content in `content/guide.mdx`
21. **Rewards**: balance, history (from `transactions`), Amazon/Walmart → creates `redemptions` doc; Pay Trash Bill + Donate as disabled stubs
22. **Profile**: address, pickup day (read-only, admin-assigned), sign out

### Phase 4 — Admin core (~1 day)
23. Admin layout + KPI dashboard (counts, material totals, revenue)
24. Users & invites: list residents; create invites for operators/depots/managers
25. Zones & depots CRUD
26. Yellow-sheet pricing editor: 7 materials, market price + customer payout %, write to `materials` + `priceHistory`
27. Redemption queue: pending gift card requests, button "Mark fulfilled" (admin emails code out-of-band during pilot)

### Phase 5 — Routes (~1 day)
28. Route builder (admin): pick date + zone → pull residents with pending pickups + pending `bagOrders` → POST `/api/route-optimize` → Google Maps Routes API (`computeRoutes` with `optimizeWaypointOrder: true`) → save ordered `routes` doc assigned to an operator
29. Cloud Function `onBagOrderCreated`: add to next route queue for that zone

### Phase 6 — Operator flow (~1 day)
30. Today's Route screen: stat row (stops/done/bags) + Current Stop card with big **COMPLETE** button + Skip / Not Out / Issue secondary buttons + Deliver bags card + next 2 stops preview
31. Scan & Confirm: QR scan + number fallback + sealed/contamination toggles + doorstep photo → updates `pickups`
32. Deliver bags + stickers: scan one sticker to confirm batch → marks `bagOrders` fulfilled, creates `stickerSheets` + `bags` records pre-issued to resident
33. Tap "Driver on the way" button on stop-start → triggers SMS stub
34. End-of-route summary → "Deliver to Depot" marks route complete

### Phase 7 — Depot flow (~1 day)
35. Incoming deliveries: list of completed routes arriving
36. Process Bag: scan QR → 7 weight fields (manual entry) → Contamination severity picker (None / Minor / Major / Severe → 0 / 30 / 60 / 90%) → Submit → Cloud Function computes points via `src/lib/logic`, writes `bagProcessing` + `transactions` + increments `users.pointsBalance` + updates `inventory` + sends SMS stub
37. Inventory page: per-commodity weight + mini bars + threshold alerts

### Phase 8 — Depot Manager (~half day)
38. Depots overview + detail + Schedule Mill Pickup (creates `millShipments`, decrements inventory)
39. Monthly report PDF export

### Phase 9 — Admin polish (~half day)
40. Zone performance table, contamination alerts (with 1st/2nd/3rd strike logic), operator leaderboard
41. Compliance notices: generate Initial Service + Semi-Annual PDFs, "Mark as mailed" button

### Phase 10 — QR generation (~half day)
42. `/api/qr-sheet`: generate PDF with 10 QR codes + printed numbers sized for Rollo thermal label stock. Create `stickerSheets` + `bags` records atomically

### Phase 11 — Security & deploy (~half day)
43. Firestore rules: per-role read/write (residents only own docs, operators read assigned routes, depot workers write `bagProcessing` in their depot, admin full access)
44. Storage rules for photo uploads
45. Seed script: 7 materials, 1 zone, 1 depot, 1 admin (Nicolas), 1 test operator, 1 test depot worker, 5 test residents
46. Deploy: Cloud Functions + rules + Vercel production

### Phase 12 — Pilot onboarding (ongoing)
47. Print QR stickers with Rollo, hand-deliver first bag batch, collect in-person feedback, iterate

Generating Users

How every account in the pilot gets created. There are three paths, one per category: an admin is set up once by the dev team, residents sign themselves up from the public site, and everyone else (operators, depot workers, depot managers) joins through an emailed invite sent from the admin dashboard.

At a glance

Who Created by Where
Admin Dev team (one-time) Behind the scenes — you receive the email + password
Resident The resident themselves Public homepage → Sign up
Operator Admin sends invite /admin → Users & Invites → Send invite
Depot worker Admin sends invite Same place — must also pick the depot
Depot manager Admin sends invite Same place — must also pick the depot

1 — The admin account (done once)

The first admin is provisioned by the dev team, because there is no admin to invite them yet. Ask the dev team for the admin email and password before you start testing. From that point on, any additional admins you need can be invited from the dashboard just like employees.

Keep the admin password somewhere safe. Every invite in the pilot flows from the admin account. If you lose access, nobody else can create operators or depot workers until the dev team resets it.

2 — Residents (self-signup)

  1. Open the public homepage in a private/incognito window.
  2. Click Sign up.
  3. Enter name, email, password (or use Continue with Google), and a real street address in the pilot zone.
  4. Submit.
Expected: The resident lands on their home screen with a 10,000-point signup bonus. No invite or approval is needed.
Address must be inside the pilot zone. If sign-up rejects an address with "outside our service area," the zone doesn't include that zip yet — ask the dev team to widen it.

3 — Operators, depot workers, depot managers (invite-only)

Employees can't self-sign-up. The admin creates them in two steps — admin sends the invite, the employee opens the link and sets a password.

Admin side — send the invite

  1. Sign in as the admin.
  2. In the sidebar, click Users & Invites.
  3. Click Send invite.
  4. Enter the employee's email and pick a role: Operator, Depot worker, or Depot manager.
  5. For depot worker or depot manager, pick the depot they'll be assigned to. That link tells the app which inventory their processed bags should update.
  6. Click Send.
Expected: The invite shows up in the list below with status pending. You can click it to copy the invite link. (Email delivery is simulated during the pilot — use the copy-link button to forward the link yourself, or ask the dev team to pull it if you closed the dialog.)

Employee side — accept the invite

  1. Open the invite link in a fresh private/incognito window.
  2. Click Accept invitation.
  3. Set a password.
  4. Submit.
Expected: The new employee lands on the screen that matches their role — operators see Today's Route, depot workers see the bag-processing queue, managers see their depot dashboard. The invite link, if opened again, reports "already used."

Common snags

What you see Probably because What to do
"Invalid or expired" on the invite link It was already used or has passed its 7-day window. Send a fresh invite from the admin dashboard.
Employee lands on the resident home after accepting Their browser session was cached before the role claim applied. Sign out, sign back in, refresh.
No Depot picker when inviting a depot worker No depots have been created yet. Create one under Zones & Depots first.
Resident sign-up says "outside our service area" The address's zip isn't in any zone. Ask the dev team to add the zip to the pilot zone.
Tip — one browser per role. Testing cross-role flows (admin invites, operator accepts, depot worker processes) is much smoother if each role has its own browser or private window. Don't sign in and out of one window — you'll lose your place.

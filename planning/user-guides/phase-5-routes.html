Phase 5 · Building a Pickup Route

How Sarah turns "these residents need a pickup" into a driving plan for James. This is the bridge between the admin dashboard (Phase 4) and the operator app (Phase 6) — you need to run this one before operator testing will work.

What you're verifying

  • Sarah can pull up pending pickups and bag-order deliveries for a zone.
  • The route optimizer returns an ordered list of stops.
  • Sarah can assign the route to an operator by name.
  • When a resident places a bag order, it gets enqueued onto the next open route for that zone.
Before you start. You need at least two residents with either a scanned bag or a pending bag order, otherwise the route will be empty. Use Maria (scanned bag from Phase 3, Scenario 4) and Tom (have him order bags as in Phase 3, Scenario 3). An operator account also needs to exist — make sure James has accepted his invite.
Scenario 1 — Build tomorrow's route

Admin Signed in as Sarah Chen.

  1. In the admin sidebar, click Routes.
  2. Click New route.
  3. Pick tomorrow's date.
  4. Pick the zone Maria and Tom live in.
  5. Click Pull pending stops.
Expected: Both Maria and Tom appear in the stop list. Maria has a pickup (her scanned bag). Tom has a delivery (his bag order). Each stop shows the address and what's happening there.

Both residents appear in the stop list

Pickups and deliveries are visually distinguished

Scenario 2 — Optimize the stop order

Admin Signed in as Sarah Chen.

  1. With the stop list showing, click Optimize order.
  2. Wait a moment.
Expected: The stops get reordered into a sensible driving sequence. A small map preview shows the resulting path. The total estimated drive time and distance show at the bottom of the list.

Stop order changes after clicking Optimize

Map preview matches the new order

Scenario 3 — Assign and save

Admin Signed in as Sarah Chen.

  1. In the Operator field, pick James Carter.
  2. Click Save route.
Expected: The route appears in the routes list with status scheduled, tomorrow's date, and James's name. If you sign in as James (on a different device or private window) he should see the route on his operator home screen.

Route saves and appears in list

James can see the route after the save

Scenario 4 — Late bag order joins the route

This scenario tests that an order placed after the route is built still gets picked up, by being tacked onto the next open route.

Resident Signed in as Tom Walker on his phone.

  1. Have Tom order another sheet of bags (repeat Phase 3, Scenario 3).
  2. Now sign back in as Sarah and reopen tomorrow's route.
Expected: Tom's new order has automatically been added to the existing route's delivery list — Sarah doesn't have to click anything. The stop count goes up by one if Tom wasn't already on the route, or the existing stop now shows the additional delivery.

New order attaches to the open route without admin action

Scenario 5 — Edit a route

Admin Signed in as Sarah Chen.

  1. Open an existing scheduled route.
  2. Remove a stop manually using its × button.
  3. Re-run Optimize order.
  4. Save.
Expected: The edit sticks. If James was viewing the route at the same time he should see it update on the next reload.

Removing a stop works

Re-optimization doesn't bring the removed stop back

Things to try that should fail

  • Trying to save a route with no operator assigned — the save button should be disabled or the form should block you.
  • Building two routes for the same date, same zone, same operator — you should get a warning or a clean error.
  • Picking a date in the past — not allowed.
If the map doesn't load. The route builder uses Google Maps. If the map tile is blank or the optimize button errors out with a Google-related message, the Maps API key may not be configured — flag it to the dev team, don't keep retrying.
